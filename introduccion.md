# 1.- Introducción

En el ecosistema tecnológico actual, la creación de software y el despliegue de infraestructuras ya no son tareas aisladas realizadas por un único técnico, sino procesos colaborativos complejos. En este contexto, la filosofía DevOps ha transformado la manera en que los equipos de desarrollo (Dev) y operaciones (Ops) trabajan, eliminando las barreras tradicionales y fomentando la integración continua. Para lograr esta sinergia, es absolutamente fundamental contar con herramientas estandarizadas para producir documentación técnica y gestionar el código. 

La documentación técnica ya no se escribe en procesadores de texto pesados como Word, sino que se trata "como si fuera código" (Docs as Code). Esto significa que los manuales, las guías de despliegue y los registros de configuración se escriben en texto plano utilizando lenguajes de marcado, se versionan para mantener un histórico de cambios y se alojan en plataformas colaborativas. Este flujo de trabajo se apoya en tres pilares esenciales:

1. **Sistemas de Control de Versiones:** El motor que rastrea cada modificación, permitiendo el trabajo en paralelo de decenas de ingenieros sin que se sobrescriba el trabajo del otro.
2. **Lenguaje de Marcas:** La sintaxis que permite dar formato visual a textos planos de manera rápida, universal y sin depender de software propietario.
3. **Sitios de alojamiento y colaboración:** Las plataformas en la nube que actúan como punto de encuentro, donde el código y la documentación se almacenan, se revisan y se despliegan.
